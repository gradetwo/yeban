Terminal and Automation Entry Points

天下同归而殊涂，一致而百虑。

Book of Changes, “Appended Judgments II” (《周易·系辞下》)

Translation: “All beneath heaven returns to one end though the roads differ; all reaches one goal though thoughts are many.” The GUI, the terminal, and MCP are different entries into the same project.

The same project can be operated through three entry points: the desktop GUI, a terminal TUI and the command line CLI, plus an MCP tool surface for AI agents. They share one project model and backend, so they do the same work with different interaction styles. This chapter gives one section each and says when to use which.

TUI

Yeban provides a terminal user interface (TUI) entry point, with source in crates/yeban-tui. It serves setups without a graphical desktop, or users who prefer working in a terminal, without opening a window; the panels and keys it actually offers are documented by that entry point's own help, not hand-copied here where they could go stale.

What each entry point suits Entry & Best for \\ Desktop GUI & Everyday arranging, notes, mixing, visual feedback \\ TUI & Terminal environments, no graphical desktop, remote shells \\ CLI & Batch work, scripts, export, CI \\ MCP & AI agents editing and querying through tool calls \\

CLI

Read the help first

The complete switch list and exit codes come from yeban-app --help; this chapter is a guide, not a replacement. Common entries:

  • [--open ] Open a given project directly (GUI or batch).
  • [--export-wav] Export the full mix; pair with --loudness-target and --true-peak-ceiling for mastering. An unreachable target fails loudly rather than silently degrading.
  • [--export-stems ] Export stems with the same backend as the MCP tool; track-selection switches can limit it to named tracks.
  • [--apply-ops] Commit a file of edit operations as one batch.
  • [--export-song-overview] Export the whole-song overview (energy/frequency/density/emotion with an anomaly summary).
  • [--print-shortcuts] Print the shortcut policy table (the same source as the GUI's Help $$ Shortcuts).
  • [--headless] Run on a machine without a display.

    • Know the feature gates

    Some switches are gated by build features. In a default build the MCP-related in-process-mcp is on — but "compiled in" is not "listening": at runtime you still need --enable-mcp-http or the environment variable YEBAN\_MCP\_HTTP=1. With --no-default-features, calling a gated switch yields a usage error naming the feature (exit code 2), never a silent ignore. Experimental exports such as --export-als and --export-logic are off by default and only compile when requested.

    MCP

    Two forms, one registry

    MCP has two forms sharing a single TOOLS registry and the same domain implementation:

  • [Form A (library form)] Hosted in-process by yeban-app, for an AI agent working on a running DAW; transport is loopback HTTP (only 127.0.0.1) or direct in-process calls.
  • [Form B (binary form)] A standalone yeban-mcp binary over stdio for batch work without a GUI.

    • Network listening binds only the loopback address, never 0.0.0.0 — a safety red line. yeban-mcp's own mcp-http is never in its default features; only the host can forward-enable it.

    Both MCP forms share one registry; network listening binds only loopback

    Don't trust hand-copied tool counts

    The tool count must be read live from the three constants in crates/yeban-mcp/src/tools.rs and the enum in schemas/mcp-tools.schema.json: numbers in documentation have gone stale repeatedly and old manuals disagree with each other. This chapter deliberately gives no concrete number.

    Some tools depend on a provider injected by the host (e.g.\ an external SVS singing service). Form B has no injector, so calling such a tool returns the providerUnavailable contract rather than pretending success.
