Projects

九层之台，起于累土。

Laozi, Dao De Jing, ch. 64 (《道德经·第六十四章》)

Translation: “A nine-story terrace begins with a basket of earth.” A project begins as an empty container with its first track: set the frame first, then add content.

This chapter covers the whole project lifecycle: how to create, open, save and reuse a project, plus Yeban's distinctive "undo is versioning" model. By the end you should be able to save work confidently, find it again, and return to any past state.

Create, Open and Save

Five entries in the File menu

The File menu has five project-related items:

  • New Empty Project: a project with only the master bus.
  • New from Template...: opens the template chooser to start from a factory or user template.
  • Open / Restore Project...: pick a .yeban file in the file dialog.
  • Save Project (Cmd/Ctrl+S): write the current project back to its file.
  • Save As (Cmd/Ctrl+Shift+S): save under a different name or location.

You can also open directly from the command line: yeban-app --open .

The startup project chooser

When you launch without specifying a project, the startup project chooser appears. It groups entry points into Recent Projects, Demo Projects, Factory Templates, User Templates, and an empty-project entry left on the “New Project” tab. A demo lets you look around without touching your work; a recent project returns you to where you left off.

Saving is atomic

Saving is atomic: content is written to a temporary location first and replaces the target only once it is complete. A power cut mid-write cannot leave a half-written project — you get either the new version or the previous one.

Project lifecycle: new/from template $$ edit $$ save $$ reopen; you can return to an older version at any time

Project Files and the Asset Pool

A project uses the .yeban extension and is the only project format. One container holds tracks, clips, notes, device chains, and the materials the project uses (kept in the asset pool, addressed by content hash).

The asset pool means "the project brings its own materials": copy a project to another machine and the audio and SFZ samples it uses travel with the container. Stem export and Save As Template both take the pool from the same source, matching the CLI and MCP behaviour (see Chapter 8).

Templates: New from Template, Save As, Factory Directory

New from template

File $$ New from Template... opens the template chooser, listing two kinds: factory templates (shipped with the app) and user templates (ones you saved). Selecting one creates a new project from that skeleton. When the list is long, the chooser reports the number of hidden rows rather than silently dropping entries.

Save as template

File $$ Save As Template... opens a dialog: enter a name, then confirm to write into the user template directory. If a template with that name already exists, the app does not overwrite it directly — it stops and asks for confirmation; cancelling writes nothing. The user template directory is created on first use; if it is unavailable, the dialog shows the error rather than failing silently.

Recent Projects and Recovery

Every successful open records the path in Recent Projects. You find it under the “Recent Projects” tab of the startup chooser and open it with one click; the list also offers a removal entry for records you no longer need. Recent projects, language and layout share one local settings store, so changing language or layout does not push recent projects out.

Open / Restore Project... is also used for recovery: after you select a container file, the app restores the scene from the history DAG and asset pool recorded in it.

Project Settings: Sample Rate, Tempo, Time Signature

On the “New Project” tab of the startup chooser you can set a few basics for the empty project; they are written into the new project:

  • Tempo (BPM): accepted range 20--999; out-of-range or invalid input is folded back into the legal domain.
  • Key signature: it can be unset (the factory state of a canonical empty project), or use sharps/flats from $-7$ to $+7$.
  • Time signature: numerator 1--32; denominator only 1, 2, 4, 8, 16 or 32.
  • Sample rate: the project's audio sample rate (Hz).

These drive later conversions: bar length comes from the time signature, and the timecode grid from the project's time signature. When a time signature is invalid, the app reports the reason literally (e.g.\ “invalid time signature, cannot compute clip length”) instead of quietly substituting a default.

Undo Is Versioning: the Time Machine

Yeban has no separate "version history" feature: every edit is a commit, and undo/ redo merely move along that commit chain.

  • Undo: Cmd/Ctrl+Z; Redo: Cmd/Ctrl+Shift+Z.
  • Time Machine (Undo Tree): Edit $$ Time Machine (Undo Tree)...; Cmd/Ctrl+Shift+H also opens it.

The Time Machine draws the whole commit chain as a graph: click any version node to return the project to that state. If there are too many older versions to fit, the panel reports how many were not drawn rather than pretending all are shown. The history DAG is saved with the project, so it is still there next time you open it.
