Export and Sharing

既以为人己愈有，既以与人己愈多。

Laozi, Dao De Jing, ch. 81 (《道德经·第八十一章》)

Translation: “The more one gives to others, the more one has; the more one shares, the more one gains.” Export and sharing hand the work to others; the more you share, the more you gain.

Once a piece is finished it needs to leave Yeban: for mixing elsewhere, for mastering, or simply as a playable file. This chapter covers what each export route produces and how to verify the result — the word "complete" alone does not mean it exported right.

WAV Export

Export the full mix

File $$ Export Audio (WAV)... mixes the whole piece into one WAV file. The dialog offers:

  • Output path: browse with Ctrl+O.
  • Sample rate: can be specified; defaults to the project's (shown as auto).
  • Bit depth: 24 by default.
  • Duration: in seconds.
  • Bus limiter: off by default; when on, rendering applies peak limiting on the bus to prevent clipping.

Read the export receipt

The export receipt gives measured readings: frame count, true peak and the limiter's workload, plus the output location. These numbers come from the actual render, not from copying back the input fields; whether the limiter was on and whether clipping occurred should be read from the receipt, not guessed.

Stem Export

When to use stems

File $$ Export Stems... renders each source-node track into its own WAV, for mixing in another program or for mastering. The master bus produces no file but is named in the skipped list — that is not a dropped track.

Export runs on a background thread so the interface stays responsive; when it finishes the status message reports how many stems were written, how many skipped and where. Each stem is a 32-bit Float WAV at the project's sample rate, with a numbered filename prefix; a stems-manifest.json index in the output directory records each file's track identity, name, byte count and hash.

Check the receipt, not just "complete"

The stem receipt starts with a exported-stems: summary line, followed by one line per stem and per skipped track. Beyond the track-level "skipped" count, look at the audio-clip dimension: rendered/skipped clip counts. If every audio clip in a stem was skipped, the message should downgrade to a warning rather than still saying merely “stems complete”. When you see “complete”, cross-checking the clip counts in the receipt is a good habit.

Export flow: pick route $$ set options $$ render $$ write $$ verify with the receipt

The CLI can export stems too: yeban-app --open X.yeban --export-stems stems/; no window, no MCP session, and the same receipt convention as the GUI.

Project Packaging and Archiving

The .yeban file is itself the package: tracks, clips, notes, device chains and the materials they use all live in one container, and saving is atomic (Chapter 2). So "sharing a project" usually means handing over that file with the assets it references; the asset pool is addressed by content hash, so opening it elsewhere does not turn it silent.

Diagnostics $$ Export Project Diagnostic Bundle produces a troubleshooting bundle, not artwork audio; attach it when asking someone to look at a broken project.
