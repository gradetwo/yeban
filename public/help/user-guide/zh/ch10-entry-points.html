终端与自动化入口

天下同归而殊涂，一致而百虑。

《周易·系辞下》

图形界面、终端与 MCP 是不同入口，通向的是同一个工程。

同一份工程可以从三个入口操作：桌面 GUI、终端 TUI、命令行 CLI，此外还有给 AI agent 用的 MCP 工具面。它们共用同一套工程模型与后端，所以做的是同一件事， 只是交互方式不同。这一章各给一节，告诉你什么时候用哪个。

TUI

夜半提供一个终端用户界面（TUI）入口，源码在 crates/yeban-tui。它给没有 图形桌面、或习惯在终端里工作的场景使用，不必开窗口；具体可用的面板与键位以 该入口自身的帮助为准，本章不在此手抄一份可能过期的清单。

三种入口各适合什么 入口 & 适合的场景 \\ 桌面 GUI & 日常编曲、写音符、混音、看界面 \\ TUI & 终端环境、无图形桌面、远程终端 \\ CLI & 批处理、脚本、导出、CI \\ MCP & AI agent 通过工具调用编辑与查询 \\

CLI

先看帮助

完整的开关与退出码以 yeban-app --help 为准；文档只是导览，不替代帮助 输出。几个常用入口：

  • [--open <路径>] 直接打开指定工程（GUI 或批处理都可接）。
  • [--export-wav] 导出整轨 WAV，可配 --loudness-target 与 --true-peak-ceiling 做母带化；目标不可达时响亮失败，不静默降级。
  • [--export-stems <目录>] 用与 MCP 同一份后端导出分轨；可配选轨开关只导点名的轨。
  • [--apply-ops] 把一份编辑操作文件当作一个批次提交。
  • [--export-song-overview] 导出整曲概览（能量/频率/密度/情绪四层与异常摘要）。
  • [--print-shortcuts] 打印快捷键策略表（与 GUI「帮助 → 快捷键速查」同源）。
  • [--headless] 无显示器机器上运行。

    • feature 门控要知道

    有些开关由编译 feature 门控。缺省构建里与 MCP 相关的 in-process-mcp 默认开，但「编译进来」不等于「正在监听」：运行时还需要 --enable-mcp-http 或环境变量 YEBAN\_MCP\_HTTP=1 才会监听。用 --no-default-features 构建时，调用被门控的开关会得到点名 feature 的用法错误（退出码 2），而不是静默 忽略。实验性导出（如 --export-als、--export-logic）默认关闭， 给了开关才编译。

    MCP

    两种形态，一份注册表

    MCP 有两形态，共用同一份 TOOLS 注册表与同一个领域实现：

  • [形态 A（库形态）] 由 yeban-app 进程内托管，AI agent 在正在运行的 DAW 上工作；传输为环回 HTTP（仅 127.0.0.1）或进程内直调。
  • [形态 B（二进制形态）] 独立 yeban-mcp 二进制走 stdio 批处理，无 GUI 环境也能用。

    • 网络监听只绑环回地址，不绑 0.0.0.0——这是安全红线。yeban-mcp 自身的 mcp-http 绝不进它的默认 feature，只能由宿主显式转发打开。

    MCP 两形态共用一份注册表；网络监听只绑环回地址

    工具数量别信文档里的手抄值

    工具数以 crates/yeban-mcp/src/tools.rs 的三个常量与 schemas/mcp-tools.schema.json 的 enum 现读为准：文档里的数字曾多次过期， 历史手册里写的值互相矛盾。本章刻意不写具体数字。

    部分工具依赖宿主注入的 provider（例如外部 SVS singing 服务）；在形态 B 里没有 注入方，调用这类工具会得到 providerUnavailable 契约的回复，而不是假装成功。
