Sampling and SFZ

荃者所以在鱼，得鱼而忘荃；蹄者所以在兔，得兔而忘蹄；言者所以在意，得意而忘言。

《庄子·外物》 / Zhuangzi, "Things External" (Wai Wu)

Translation: The trap exists for the fish; once you have the fish, you can forget the trap. Note: SFZ files and samples are the trap; the musical intent is the fish. Do not let file management eclipse the sound.

A synth computes sound; a sampled instrument plays recordings. Yeban's sampling side is built around SFZ: a text file describing which key range, which velocity range, which audio file, and how to transpose it. The audio stays on disk. Understanding that split is how you tell "no sound" apart from a missing file, an uncovered key, or the wrong entry point.

What SFZ is, and what it is not

SFZ is a text definition file. It does not contain PCM, and it does not pack a whole sample library into the project; it lists regions and sample paths. Yeban parses the SFZ, flattens the region table into a playable instrument, and chooses regions by note and velocity. The project stores only the path of the SFZ bound to a track, so the project file stays small, but moving machines, deleting a library, or relocating samples can break that path.

Only one main source sounds on a track: the dispatch order is drum machine > SFZ > poly synth. If a track carries a drum machine, an SFZ, and a synth at once, the drum machine wins and the other two are ignored. That is the established "one main source per track" rule, not a bug.

Three entry points, three destinations

Several places in the UI say "SFZ" or "sample library"; they do not do the same thing:

Entry point & Actual action & Binds current track? \\ Device rack "+ Load SFZ" / left-library sample entry & Opens the instrument manager; choosing an item loads it onto the current track & Yes, writes the track sampler \\ Top module bar "Load SFZ" & Chooses an SFZ as the export/audition source and reports regions plus a probe reading & No, does not change track binding \\ File menu "Load SFZ sound library..." & Same module action as the top bar & No, current implementation does not write track binding \\ What the three SFZ entry points actually do

To put an instrument on a track, use the device-rack empty-state button or the left-library sample entry: select an item and load it onto the current track; the project commits a SetTrackSampler. The top "Load SFZ" is the bypass for "use this source for the whole project's audition/export": it keeps the instrument in a memory slot for the next export and does not replace the current track's source. If its default path has no file, it opens the instrument manager instead of reporting a jargon error.

Key ranges, root keys, and velocity layers

Every SFZ region answers at least four questions: which keys it covers (lokey/hikey), which velocities it covers (lovel/hivel), where its root is (pitch\_keycenter, default 60), and which file it plays (sample). A note triggers only inside the region; when several regions cover the same key and velocity, they layer. That is what layered sampling means.

Each cell is one "key range × velocity layer" group. A real SFZ need not fill the whole table: if only C3 at medium velocity is written, C4 has no sound; if only high velocity is written, a light touch does not trigger. When "some keys sound, others do not", check region coverage before suspecting the engine.

The root key determines transposition. If a sample was recorded at C3 but pitch\_keycenter says 60 (C4), playing C3 sounds a whole octave low. Yeban's load report performs notation adaptation: when the file writes key names and the sample has no embedded root, evidence is insufficient and no automatic shift happens; the receipt warns that the octave may be off. The project model supports note\_octave\_override, but the current UI has no separate octave knob, so do not expect one click to fix every library.

Velocity response comes from amp\_veltrack (default 100%, range $-100$–$100$) plus an optional amp\_velcurve\_N point table; key-dependent loudness comes from amp\_keytrack (default 0 dB/key, range $-96$–$12$). Most libraries need neither changed; if an entire velocity layer is too loud or soft, inspect the library first, then consider changing the Yeban side.

MPC: sampling is not a sound pack

Akai and Roger Linn released the MPC60 in 1988: 12-bit sampling, sixteen velocity-sensitive pads, a built-in sequencer and swing. DJ Premier, Pete Rock and J Dilla all used MPC series instruments over long careers; what changed music was not “it can sample”, but that sampling, performance and sequencing became one instrument.

The lesson for SFZ is direct: a region is not “a sound file”, it is one trigger. Which root and velocity layer the sample uses decides what you hear when you hit that pad; the pad's feel comes from performance and timing, not from the file format. Yeban's SFZ only handles the mapping of key range, root, velocity and sample; it does not handle MPC swing. For an MPC-style drag, solve it in MIDI/drum-machine timing (Chapter 9 covers micro\_timing\_ticks); do not expect a change to an SFZ region to deliver it.

So when building a sampled instrument, do two things first: choose the right root and velocity layers so each pad “feels like that instrument” when pressed; then treat performance (velocity, timing, repetition) as part of the arrangement. An “MPC feel” is not a sample pack; it is sample selection plus pad performance plus timing.

Boundaries: Yeban currently has no sixteen-pad MPC screen and no MPC swing knob. This chapter can reproduce sample mapping and velocity layers; timing and pad performance belong to the MIDI/drum-machine side. Do not use a looped sample to pretend it is “MPC performance”.

Supported files and fallbacks

Yeban dispatches samples by suffix: .wav/.wave go through PCM/float WAV decoding; other common formats (FLAC, OGG, and so on) go through the general decoder. Both legs preserve channels, and samples with more than two channels are explicitly rejected rather than silently folded to mono.

Situation & Yeban's behavior \\ Mono/stereo WAV, FLAC, OGG, etc. & Decodes normally; stereo keeps left and right \\ Sample rate differs from project & No resampling; playback-rate conversion, original rate kept in the report \\ Sample missing or unreadable & Falls back to a 440 Hz in-memory sine and lists the path under missing; not a silent success \\ More than two channels & Explicitly rejects that sample \\ sample=*silence & Built-in silent pseudo-sample: the region exists and triggers, but produces no sound \\ \#include missing or unmatched & Loading continues; each issue goes into include\_issues \\ How sample reads succeed and fail

The fallback sine is a diagnostic signal, not a substitute timbre. A clean 440 Hz sine means the sample was not read; inspect the missing list and fix the path or file instead of reaching for EQ.

Each track's SFZ voice pool holds 16 voices. Beyond that, the existing steal policy replaces older voices and accumulates a steal count. That ceiling is enough for ordinary arrangements, but large ensembles or long release overlaps should expect stealing rather than infinite polyphony.

Sample-library management

Yeban manages a single sample-library root outside the project directory. When no library is installed, the device-rack sample-library button reads "Download sample library (about 9.4 GiB)"; once installed, the same button becomes "Verify sample library". Downloads happen only when the user clicks, never silently in the background.

A pack is verified by SHA-256 and size before installation; a failed check writes nothing and leaves no half-installed directory. Deleting a library lists the tracks still bound to it and warns that they will lose their source; deletion is explicit, not "cache cleanup". Paths inside the library are stored relative to the library root as assets/samples/..., so they survive a machine change as long as the root is in the same place. Absolute paths outside the library are not migrated and may break elsewhere.

Troubleshooting

  1. No sound at all: first confirm the track is actually bound to an SFZ (not merely that the top "Load SFZ" was clicked), then check region coverage, then whether samples are missing.
  2. Only some keys sound: check lokey/hikey. Layered libraries usually do not write a region for every semitone.
  3. Everything is an octave low/high: check pitch\_keycenter and the library's notation. There is no octave knob in the current UI; use the receipt's hint first.
  4. Velocity feels wrong: check amp\_veltrack and amp\_velcurve\_N; not every library maps 0–127 linearly.
  5. Silent after changing computers: check whether the library root moved and whether the project stores a relative path or an absolute path outside the library.
  6. Library installed but the list is empty: click "Verify sample library" and check that the root is writable and the pack is complete; do not read an empty list as "no instruments".
