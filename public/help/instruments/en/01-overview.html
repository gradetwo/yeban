Instruments and Tracks

工欲善其事，必先利其器。

《论语·卫灵公》 / The Analects, Book XV (Wei Ling Gong)

Translation: To do a job well, sharpen your tools first. Note: learn how tracks, instruments, and sound sources connect before reaching for another preset.

This chapter explains how tracks, instruments, and sound sources relate in Yeban, and how the factory synthesizer presets are named and loaded. It describes only behaviour that exists in the live code and can be observed in the application or in project data.

Three signal paths

Yeban tracks fall into three groups by sound source. A MIDI synthesizer track produces sound through one instrument. An audio track plays audio clips and has no instrument. Auxiliary and master bus tracks only carry summing, effects and faders; they do not host instruments. After the instrument, a track's signal passes its insert effects, fader, and pan before it reaches a bus.

A track has at most one sound source. If a track somehow contains drum machine, SFZ, and poly-synth configuration at the same time, the engine dispatches in the order “drums first, then SFZ, then poly synth”; the suppressed sources do not sound together. This is an engine verdict, not a switch in the interface.

Tracks and instruments

When a MIDI synthesizer track is created, the application installs the default Yeban PolySynth and ensures that the track has a route to the master bus. Audio, auxiliary, and master bus tracks never receive an instrument.

There are two entry points for changing an instrument:

  • The bottom device rack (F9): inspect the current track's device

    • chain and replace or add instruments and effects.

  • The left sound library: browse factory synthesizer presets and

    • SFZ instrument libraries; the selected preset becomes the current track's instrument.

Changing a preset writes that preset's device parameters to the track's instrument device. Existing notes and clips are not lost when the timbre changes. If a track has no usable instrument, the application installs the default synth before playback or editing.

Six factory synthesizer presets

Factory synthesizer presets use the synth: prefix. The interface gives the same preset different display names in different panels: the left library uses a timbre description, while the device rack and arrangement use “instrument type + timbre”. The engine name in the table below is the canonical name used in project data and on the engine side; use it when writing scripts, debugging a project, or comparing exports.

Different labels in different panels are historical UI wording, not different timbres. To determine which preset a track really uses, inspect the device parameters or the preset ID in project data, not a single panel's label.

Saving and loading presets

The “Native Preset Library” entry in the File menu lists factory-embedded presets and user-library presets. It can apply a preset to the current track and save the current track as a preset. Presets have two scopes:

  • Instrument preset (instrument): stores the instrument identity and

    • instrument parameters; applying it to another track replaces the instrument.

  • Track snapshot (track): stores the device chain, sends, fader,

    • pan, mute/solo, and macros; it does not require a portable instrument.

The interface button “Save current track as preset” uses the instrument-preset path. It requires the current track to be bound to a factory-registered SFZ instrument. Built-in synth tracks and audio tracks have no portable instrument identity and are rejected with the reason shown in the preset panel. To keep a built-in synth track's whole setup as a template, use a track snapshot (scope: "track" in project data) or “Save as Template”, not an instrument preset.

The six factory synth presets are parameter combinations of built-in timbres, not instrument presets in the user library. They do not appear in the result of “Save current track as preset”, and they do not depend on user-library files.
