## 背景（先测后改，`AGENTS.md` §6）

**这个数字在数什么**：单位＝**个/遍**，对象＝一次 `ClipPlacement` 的循环语义与其界面表现。
现读（2026-11-01，`main`）：

| # | 事实 | 出处（符号级） |
| :--- | :--- | :--- |
| 1 | 循环数据的**唯一真相**在模型层：`ClipPlacement::loop_repeat() -> Option<LoopRepeat>`（区间 `[start, end)` + `iterations`），`None` ＝ 单遍 | `yeban-model/src/loop_plan.rs` |
| 2 | 渲染/展开三处共用同一实现（引擎／MCP／界面剪辑几何），`#249`/`ADR-0010 D4` 明文登记，pickup 段原样播一遍、循环段按遍搬运 `source_offset` | `yeban-app/src/audio_clip.rs`、`yeban-engine/src/audio_clip.rs` |
| 3 | 界面编曲轨上**只画一个矩形**：矩形时长＝placement 全时长（**已含**全部重复遍，时间轴长度口径是**诚实的**），矩形内部**没有**任何"这是循环／重复了 N 遍"的视觉或树内表示 | `ui/app.slint` 剪辑模板 ＋ 报告 §5.2 树读数 |
| 4 | 报告复现（单位＝条/遍/个）：工程 **2** 条循环摆放 —— Timpani 起 `92160`、长 `153600`、区间 `0–3840`、重复 **40** 遍；Ostinato 起 `30720`、长 `276480`、区间 `0–3840`、重复 **72** 遍；渲染展开 **2962** 个音符 | `~/zimmer-ui-mode-report.md` §5.2 |

⚠ 规范未规定循环的界面表现（架构/路线图无此条；UI/UX 稿是 Advisory）⇒ 规范缺口，按 §5.7 登记。

## 决定（四选一）

| 选项 | 内容 | 代价与风险 |
| :--- | :--- | :--- |
| **A 维持现状** | 单一矩形即"正确"：时长口径诚实，重复信息**选择不显示** | 零代码、零基准；但 40/72 遍这种**量级信息**用户完全不可见，与报告口径的"缺口"并存 |
| **B 徽标** | 剪辑头加"×N"派生徽标（读数来自 `loop_repeat()` 既有展开，⛔ 界面不重算） | 小面：模板＋桥接元数据；基准重录一轮；语义最小、无新交互 |
| **C 区间分割/底纹** | 矩形上画出循环区间边界（每遍分隔或区间底纹） | 中面：剪辑几何参与绘制；密集重复（72 遍）下**视觉噪声**需设计裁量 |
| **D 可编辑循环区** | 界面上直接拖拽循环区间端点/改遍数（走撤销链） | 最大面：新手势＋新 `Op` 语义＋判据全套；且**先有 B/C 的显示**才谈得上编辑 |

**建议**：无（显示密度与交互深度是产品姿态，⛔ Agent 不代选）。若批 `D`，隐含先批 `B`/`C` 之一的显示层。

## 后果

- 批准前，`N-UI-2` 的口径是"**已登记的规范缺口**"：功能正确（渲染与时长诚实）、表现缺失。
- 任何批准批次都走标准 UI 切片流程：判据先行（注入⇒变红）、CI 判决、`gate=goldens` ＋人工复核基准。
