# ADR-0066 — 铅笔左键拖拽的语义未定（缺口 D-UI-12：拖动整格是死代码，唯一的时值手势要选区）

- **状态**: **Proposed（待人类批准；⛔ Agent 不代签）**
  —— 本票是**零代码票**：`line/zimmer-ui-write-surface` 上**没有**任何与拖拽时值有关的实现，
  也没有待撤回的补丁。落选哪一档都不需要改模型/引擎，只需在 `host.rs` 的拖拽通道里
  多接一条臂（或维持现状并把缺口写进 UI 文档）。
- **决定者**: 待人类裁决
- **关联**: 缺口 `D-UI-12`（本线创作验收实测登记）；姊妹缺口 `D-UI-13`（命中不分作用域，已修，
  见 `ADR` 无需 —— 修复带判据 `crates/yeban-app/tests/d_ui_13_roll_hit_scope.rs`）；
  `crates/yeban-app/src/input.rs:390-420`（`ToolDrag` 五格）、`input.rs:458`
  （`Self::Pencil => ToolDrag::ResizeDuration`）、
  `crates/yeban-app/src/host.rs:11342-11373`（`begin_note_drag` 的工具门）、
  `host.rs:11144-11157`（拖拽两格已接线的表格）、
  `host.rs:9554`（`Action::ResizeSelectionDuration` 键盘臂）、
  `host.rs:10737`（`resize_duration_delta_for` = 一个吸附网格 `ROLL_SNAP_GRID_TICKS`）
- **日期**: 2026-11-02

## 背景（全部现读，⛔ 不采信报告措辞）

1. **工具矩阵"左键拖拽"那一列，五格里只有两格有生产消费者**。`input.rs` 自己的表格与
   `host.rs:11144-11157` 的注释都是这个口径：
   `MoveNote`（选择工具）与 `AdjustVelocity`（力度工具）已接线，
   `ResizeDuration` / `SliceAcross` / `EraseSweep` **⛔ 未消费**，每条变体的文档里写着
   "裁决未定"。
2. **铅笔的拖拽格恰好是 `ResizeDuration`**（`input.rs:458`）。于是今天的真实行为是：
   选中铅笔工具 → 在音符上按下并向右拖 → `begin_note_drag` 在**工具门**这一步就返回
   `false`（`host.rs:11371-11373`），`.slint` 侧据此**不**接管手势 ⇒ 这次拖动被
   滚动区吃掉，变成**横向滚动**；工程一个字节没变，`roll-edit-status` 一个字没写。
   ⇒ 对用户而言这是"拖了，什么都没发生"，且**没有任何拒绝原因可读**。
3. **唯一已接线的时值手势是键盘**：`Shift+←/→` → `Action::ResizeSelectionDuration`，
   幅度为**一个吸附网格**（`resize_duration_delta_for` = ±`ROLL_SNAP_GRID_TICKS` = ±240 tick），
   作用域是**选区**（`selected-ulids`），空选区 ⇒ 0 提交、返回 `false`（不吞键）。
4. **两条路合起来在创作现场是死角**。第二首作品（模拟人类手势面，dist9/rerun8）计划
   316 次落笔，按手势分三档（`/tmp/zimmer_creative/probe_dur.py` 的现读口径）：
   单击默认时长 **136/136 成**、单击后走"预设 960 tick"的 **36/36 成**、
   而**拖拽改时值那一档 0/144 成** ⇒ 144 颗音符（占计划落笔的 **45.6%**）根本没进工程。
   当时归因于"拖不出时值"，复核后的准确归因是两件事叠加：
   - `D-UI-13`：**命中测试不分作用域** ⇒ 多剪辑工程里点击选中打不到正在编辑的那颗
     ⇒ 选区为空 ⇒ 键盘 `Shift+→` 依 ③ 直接 0 提交。此条已修（`8ca460ba`，带五条判据）。
   - `D-UI-12`（本票）：即便选区可用，**鼠标这条路上仍然没有任何时值手势**
     —— 铅笔拖拽是死代码，选择工具拖拽是平移（`MoveNote`，不改时长）。
   - ⚠ 读数口径留痕：那 144 例当时的"拒绝原因为空"**不成立** —— 控制面对 `role=text`
     单元格回 `value: null`，正文在 `label` 键里（`probe_dur3.py` 实测）。本票第 2 条那句
     "`roll-edit-status` 一个字没写"是**从代码读出来的**（工具门 `return false` 之前
     没有任何 `set_roll_edit_status`），⛔ 不是从那次读数推出来的。
5. **为什么不照抄参考文档就能收工**：`docs/YEBAN_DESKTOP_UI_UX_AND_INTERACTION_REDESIGN.md`
   已于 2026-10-06 经负责人裁决**降级为 Advisory**（AGENTS.md §1 第 3 条），不能作为绑定
   实现规范；而代码注释里悬着的两个子问题也不是文档能一键回答的：
   - **命中区**：拖音符**任意位置**改时值（铅笔的"画完即调"直觉）vs 只有拖**右边缘**
     （DAW 惯例，但与"选择工具整块平移"共用同一条 TouchArea ⇒ 需要边缘判定与
     命中优先级）；
   - **提交形状**：`move` 期只写草稿、松手**恰好一个** `Op::SetNoteTiming`（与
     `MoveNote`/`AdjustVelocity` 两臂一致，判据 `move_arm_d_*` 钉的就是这个形状）vs
     每步提交（会把一次拖动碎成几百步撤销）。第二问在既有工程纪律下**其实没有悬念**，
     真正待裁的是第一问与"哪个工具拥有右边缘"。

## 为什么现在必须定

目标之一是用**只用鼠标/键盘的人类手势**做出第二首 3 分钟作品。时值是作曲动作，不是可选美化：
本票不修，UI 面上任何"改变已有音符时长"的自动化脚本都必须退化成
`点击选中 → Shift+→ × k` 的离散按键序列（k = Δtick ÷ 240），一颗四分→全音符要按 12 次。
这既是效率问题（k 次提交 = k 步撤销），也是**体验正确性**问题：
人类用户会拖，拖了没反应，且界面不给原因。

## 选项

| | 内容 | 代价 | 与本仓库纪律的关系 |
|:--|:--|:--|:--|
| **A**（推荐） | **右边缘才有语义**：铅笔/选择工具下，指针落在音符右 `RESIZE_GRAB_PX`（建议 6px）内 ⇒ 拖拽 = 改时值；其余区域维持现状（选择工具=平移，铅笔=新建）。一次拖动 = 松手**恰好一个** `Op::SetNoteTiming`，草稿写 `.slint`，夹紧 ≥ 1 tick，吸附到网格 | 新增边缘命中 + 一个 `ToolDrag::ResizeDuration` 消费臂 + 判据（形状照抄 `roll_edit_tools.rs` 的 `move_arm_*`） | 与 `UI-NOTE-003` 的"工具拥有语义"一致；⛔ 不改既有两臂；撤销粒度与既有臂同形 |
| **B** | **铅笔拖拽整块 = 改时值**（不区分右边缘）：铅笔下拖动命中音符 ⇒ 时值跟随指针 x | 最小实现，但**铅笔下无法平移**（当前铅笔本来也没有平移，损失为零）；⚠ 与"铅笔=画新音符"的按下语义冲突：按下已经落了一个新音符，同一手势再拖它改的是**这颗新音符**的时长 | 语义上是"画完即调"，对连续作曲友好；但把"新建"与"编辑既有"绑死在同一手势，撤销栈里每次画音符都可能多一步 |
| **C** | **维持现状 + 文档收口**：明确登记"UI 面无鼠标时值手势，时值只走 `Shift+←/→`"，把 `ToolDrag::ResizeDuration` 标为 `Deferred` | 零代码；但 4. 的死角仍在（选区可用后按 k 次键），且"拖了没反应且不报原因"留给用户 | ⛔ 对用户不可解释的体验退化，仅作为 A/B 都否决后的兜底 |

## 建议与后果

建议 **A**。理由：A 是唯一同时满足「一次拖动 = 一步撤销」「不改既有两臂」「鼠标路径
自洽（不需要先学会键盘组合键才能改时长）」三件事的方案；B 的实现更省，但它让
"新建音符"这个动作附带一个未被要求的编辑副作用，撤销栈里会多出人类没有意图的步骤。

无论选哪档，`D-UI-13` 的修复都要**独立成立**（它改的是命中作用域，与本票的拖拽语义无耦合）；
若选 C，建议同时补一条**拒绝可见性**：任何未消费的 `ToolDrag` 分支在按下的工具不是
选择/力度工具时，把逐字原因写进 `roll-edit-status`（现状是完全静默，与 `#166` 的
"⛔ 不静默丢弃"纪律不一致）。

## 判据落点（若选 A 或 B）

- 拖动前后 `duration_ticks` 的**增量**等于按网格换算的值（⛔ 不断言浮点像素相等，
  与 `roll_edit_tools.rs` 里 `DRAG_HOST_DY = −28px ⇒ +2 音高` 同一手法）；
- 一次拖动 = **一次** `commit_ops`（数撤销栈步数，⛔ 不数 `move` 事件数）；
- `cancel`（`PointerExited`）⇒ 丢弃草稿、工程逐字节不变；
- 边缘命中区（A）：落在**非**右边缘 ⇒ 走原有语义（选择工具仍平移、铅笔仍新建），
  由既有 `move_arm_*` / 铅笔判据守住不回归；
- 未选片时（作用域为空）⇒ 命中的仍是可见择优的那颗（`d_ui_13` 判据 ⑤ 的控制臂口径）。
