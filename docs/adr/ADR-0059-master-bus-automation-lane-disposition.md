- **决定者**: 待人类

## 背景（先测后改，`AGENTS.md` §6）

**这个数字在数什么**：单位＝**条**，对象＝`automation.rs` 里"界面可见自动化泳道"的投影集合对
`project.master_bus_track_id` 的处理。现读（2026-11-01，`main`）：

| # | 事实 | 出处（符号级） |
| :--- | :--- | :--- |
| 1 | 泳道投影显式过滤主总线：`.filter(\|track\| track.id != project.master_bus_track_id)`（同一文件另有多处 `!= master_bus_track_id` 的同口径臂） | `automation.rs` |
| 2 | 模块文档逐字写着"因此 `master_bus_track_id` 那条轨道上的泳道被**跳过**（判据断言跳过是有意的）" ⇒ 排除**不是疏漏**，是被常驻判据钉死的设计 | `automation.rs` 模块注释 |
| 3 | UI 侧读数文档同口径：`bridge.rs` 的泳道读数条目写着"全部自动化泳道（**非主总线轨道** → `AutomationTarget::Ord` 序）" | `bridge.rs` |
| 4 | 报告复现：本工程**恰好只有 1 条**自动化泳道，目标就是主总线音量 ⇒ 投影泳道数 **0**、界面泳道标签 **0**、树泳道节点 **0**（单位＝条/个；三层同时为 0） | `~/zimmer-ui-mode-report.md` §3.3 |

⚠ 规范（架构/路线图）**没有**规定主总线自动化该不该出现在界面上；UI/UX 稿自 2026-10-06 起是
**Advisory**。⇒ 这是产品缺口，按 `AGENTS.md` §5.7 登记，不自行选一种落地。

## 决定（三选一）

| 选项 | 内容 | 代价与风险 |
| :--- | :--- | :--- |
| **A 维持排除** | 主总线自动化今天不可见＝**既定设计**；把理由落成批准记录 | 零代码、零基准；但报告口径下用户**无法**编辑/看到主总线音量曲线，功能缺口继续存在 |
| **B 放开为可编辑泳道** | 主总线行进入投影＋界面出现泳道与"当前值"标签，编辑走与轨道泳道同一条提交链 | 反改钉死"跳过是有意的"的判据；`automation.rs`／`bridge.rs`／`host.rs`／`app.slint` 四处同改；若默认演示工程随之加入主总线泳道 ⇒ **5 张基准重录**（`HD-56` 路径） |
| **C 只读显示** | 曲线与标签出现，但⛔ 不接受编辑手势 | 介于两者之间；仍要反改判据与重录基准，却留下一条"看得见摸不着"的**不对称**（与 `ADR-0052` 对空壳控件的诚实性口径相仿，需写明理由） |

**建议**：无（三条是产品姿态，⛔ Agent 不代选）。

## 后果

- 批准前，`U-12` 在本仓的口径是"**已登记的既定设计**"，不是"待修的缺陷"；报告把它列为缺口
  是以用户可见功能为准，两者不冲突。
- 批 `B`/`C` 属 UI 功能切片，走标准流程：判据先行（注入⇒变红）、CI 判决、基准复核。
