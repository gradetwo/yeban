# ADR-0078 — 内置器件延迟的离线推导口径：磁带与软削波不写模型声明

- **状态**: **Proposed**（待人类批准；按 AGENTS.md §5.7，agent 裁决先标 Proposed。T-DRUM-9 第二阶段已按本票实施——审计经 Synapse 管理侧评审通过，裁决点即审计 §8 的路径裁决；人类改判后更新本文件）
- **决定者**: T-DRUM-9 线（审计＋管理侧评审）提出，待人类批准
- **关联**: `ARCH-PDC-001`（延迟上报与补偿）；ADR-0062（磁带 PDC 口径，本 ADR 部分取代其「计入声明」一条，见 D4）；`crates/yeban-render/src/render.rs`（`track_latencies`）；`crates/yeban-render/src/inserts.rs`（`limiter_latency_frames` 先例与本 ADR 的两条新推导）；`crates/yeban-dsp/src/tape.rs`、`crates/yeban-dsp/src/clipper.rs`（读数与公式）；`crates/yeban-engine/src/rt.rs`（实时插入池四级）

## 1. 背景

PDC 的账只认一个来源：模型层 `DeviceDefinition::latency_samples` 的声明值。鼓机生成器给每台生成器件写声明 0，但其中两族在离线链里真执行、真延迟：

- 磁带饱和：固定 2 倍过采样往返 31 帧；wow/flutter 武装时再加中心延迟名义值（lofi 预置 69 帧 @48 kHz）。
- 总线软削波：过采样级联往返（级数随 `clipper_oversample`）。

T-DRUM-9 第一阶段审计实证：14 个出厂风格全部中招，生成工程的鼓声在离线渲染里比计划晚 62–162 帧（按审计口径，见 §4 的实测订正）。仓内有两条互相冲突的先例：

- **先例甲（DSP 文档，ADR-0062 一系）**：延迟写进模型声明。声明被实时与离线两条通路共用。
- **先例乙（限制器）**：声明保持 0，离线累加处（`track_latencies`）按参数推导后加；实时账不受影响。

关键事实：两条通路的**执行面不同**。离线插入链完整执行磁带与削波；实时插入池只有采样延迟、通道条、混响、卷积混响四级，根本不执行这两族。照甲做，离线对齐了，实时计划却会为不存在的延迟多补其余支路，实时反而错位；且逐件链校验（`LaneChainDeviceLatency`）会开始拒绝生成器自己写的磁带器件（声明非零即拒入链）。照乙做，与限制器先例同形，且有现成判据。

## 2. 决定

### D1 走先例乙：引擎自知的固定延迟在离线累加处推导，不写声明

`yeban_render::render::track_latencies` 在声明求和之外加三项推导：限制器前瞻（既有）、磁带、软削波。判决点与运行态的建成判定同构（来源槽＋净化后参数的武装门），旁通不计。

### D2 两条推导的公式与读数来源

- **磁带**（`inserts::tape_latency_frames`）：按来源参数构造 `TapeSaturation`、配置到渲染采样率后读它自己的读数——武装时 `latency_samples()`（31）＋调制武装时 `modulation_latency_samples()`（中心名义值）。公式只存在于 `yeban-dsp` 一处，推导侧不复制。`track_latencies` 因此新增 `sample_rate` 参数，调用方传本次渲染的采样率。
- **削波**（`inserts::clipper_latency_frames`）：级联总延迟 `2 · OS_LATENCY · (1 − 2^(−s))`（s = 过采样级数），整帧就近取整（半值向上）：1× = 0、2× = 31、4× = 47、8× = 54。

### D3 边界：声明字段仍是插件／用户器件延迟的唯一事实源

本裁决只覆盖「引擎自知、参数可推导、且只在离线链执行」的内置器件延迟（当前三族：限制器、磁带、软削波）。插件与用户器件的延迟仍只能来自声明 [ARCH-PDC-001]，引擎不测、不猜。实时计划继续只认声明，一字不改（守卫判据在 `yeban-engine` 的 snapshot 测试）。

### D4 对 ADR-0062 与 DSP 文档口径的取代

ADR-0062 与 `tape.rs` / `clipper.rs` 模块文档中「设备作者须把过采样往返延迟计入 `latency_samples` 声明」一条，自本 ADR 起对**内置磁带与软削波**失效，改为 D1 的离线推导；两处文档已同步改指向推导面。ADR-0062 的其余裁决（参数、位置、链序）不受影响。

### D5 静态边界（如实登记，不在本线消除）

- 推导是计划期的静态读数。静态不武装、但有非恒等自动化泳道的器件会被运行态强制实例化，其块边界拉起后的延迟不在静态账内——与限制器读数只读静态参数同一条边界。
- 逐件链（lane 链）层没有 PDC：模型校验只拦**声明值**非零的器件，拦不住「声明 0 但真实非零」的器件（磁带可合法入链、离线真执行、无补偿）。该缺口登记为已知缺口（`docs/DEVELOPMENT_LEDGER.md` §5.2），本线不实现逐件级补偿；未来生成器若给逐件链加磁带等族，须先单独立项（量级 L）。

## 3. 行为变更（W4）

修复后，既有生成工程的鼓声在离线渲染里整体**前移**到与计划对齐的位置：只带总线削波的风格前移 47 帧；带磁带的风格前移 78 帧；lofi 前移 147 帧（48 kHz 下约 0.98–3.06 ms）。鼓 loop 交付物须按新口径重渲（管理侧在合入后执行）。实时播放不受影响（实时计划与执行面均未动）。

## 4. 实测订正（对审计 §5 数字的修正）

审计的削波数字（4 倍 = 62）来自「级数 × OS_LATENCY」的推算，审计 §10 已自明未做渲染实测。第二阶段以冲激响应实测钉死：级联每级的往返延迟是 `OS_LATENCY` 个**该级自身速率**的样本，折回基础采样率逐级减半，质心为 2× = 31.000、4× = 46.500、8× = 54.25。故 4 倍档入账 47（非 62），路径合计相应订正为 47 / 78 / 147 帧。磁带侧数字（31、lofi 调制 69）与审计一致，实测质心 31.000 复核通过。

## 5. 代价

- `track_latencies` 签名新增采样率参数，四个生产调用点（app 导出、MCP 渲染 ×2、song overview）同步改传渲染采样率。
- 离线推导与 DSP 实现形成耦合：削波级联结构或磁带读数若变更，推导公式须同改——已用冲激实测值与渲染级对齐判据双向钉住，公式漂移会先红在判据上。
- 4 倍档残余半帧（0.5 样本 ≈ 10 µs @48 kHz）在帧网格之下，不可补，如实登记。
