# 模块工作线登记（常驻 subagent — **要复用，⛔ 不用一次就丢**）

> 负责人指令（2026-10-13）：「按模块多线异步推进开发，多利用 GitHub 的 CI/CD 来跑耗时和耗 CPU 的事情，
> 容易出错的操作或者多次出错的操作，你要想办法自己造工具简化操作和避免错误」
> 及「另外每个模块的 subagent 要复用，不要用一次就不用」。
>
> 本文件是**集成者（主会话）**维护的登记表：一行一个模块线，记它的常驻 subagent id 与当前任务。
> ⚠ **每个会话接手时先读本文件**，再用 `send_message` 把下一件交给**同一个** subagent ——
> ⛔ 不要为同一个模块反复新建 subagent（那会丢掉它的上下文与教训）。

## 1. 不变的边界（⛔ 每个 subagent 都必须遵守）

| 项 | 规矩 |
| :--- | :--- |
| **写者** | 一个文件同一时刻只有一个写者。**每个 subagent 只准改它的模块目录**（见下表 `允许改` 列）。 |
| **根级文件** | ⛔ subagent **一律不准**改：`Cargo.toml`、`Cargo.lock`、`.github/**`、`scripts/**`、`schemas/**`、`docs/**`。那些归**集成者**独占。（唯一的例外是集成者在下单时**逐字**授权的那一个文件。） |
| **台账** | ⛔ subagent **不准**改 `docs/ledger/**`。它只**报告**判决与读数；由集成者入册（台账是单行巨石，两个写者必冲）。 |
| **worktree** | subagent 在自己的 `line/<模块>` 树里干活；`scripts/dev/worktree.sh add <name>` 建树。⚠ 该树上游被配成 `refs/heads/main` ⇒ **⛔ 绝不用 `git push -u`**、⛔ 不推远端；由集成者快进合并并推主干。 |
| **判决** | ⛔ subagent **不准**声称"CI 绿"。本地绿只是参考；由集成者用 `scripts/dev/verdict-by-sha.sh <sha>` 读回判决。 |
| **红要取真红** | 判据必须**注入实测变红**（⛔ 编译不过不算行为红）。 |

## 3. 工具（自造，避免重复出错）

| 工具 | 治哪个反复出错的操作 |
| :--- | :--- |
| `scripts/dev/verdict-by-sha.sh <sha>` | 读回**某个提交自己**的判决。我手写过 5 次轮询脚本，且每次都踩同样的三个坑（轮询无上限、把 skipped 当绿、`gh` 缓存目录不可写）。本工具固定输出并**逐条列出被跳过的腿**。 |
| `scripts/dev/worktree.sh {add,rm,land,list,path}` | worktree 生命周期（既有）。 |
| `scripts/gates/run-gates.sh light` | 全部机械守卫 + fmt（既有）。 |

## 4. 每次派单的固定形状（集成者照抄）

1. **读数确认**：`git -C <树> status --short` 必须干净（或只有你自己的 `.tmp*`）。
2. **任务**：一句可判的目标 + 它归哪个规范 ID。
3. **交付**：worktree 名、分支名、**完整 40 位 sha**、四门退出码、判据名、注入红读数。
4. **不准**：改根级文件、改台账、推远端、声称 CI 绿。
