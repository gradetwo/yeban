# 阶段状态表（`ROAD-M-1-001` … `ROAD-M4-010`，46 项）

> **这份文件回答"每个阶段的路线图项现在什么状态、还剩几项"。**
> 它由 `scripts/gates/check_phase_status.py` 在每次 `run-gates.sh light` 里机械校验
> （照 `docs/ledger/gate-status.md` 的成功先例：那张表管门禁，这张表管阶段项）。

维护纪律（**必须遵守**，否则这张表会变成谎言）：

1. 状态的取值**只有三个**：`已完成` / `部分` / `PENDING`（与 `gate-status.md` 同一套词，便于互相引用）；
2. 标 `已完成` / `部分` **必须**给出**可复跑的判据**（run id / 命令 / 测试名 / 台账的路径 + 小节号）；
3. `PENDING` 必须写清**为什么**，并给出"它确实还不存在"的可复跑痕迹
   （例如 `ls <目录>` 报不存在、`grep` 命中 0）—— **不许把"没查"写成 `PENDING`**；
4. `ADR-0001 D7`：**不具备条件的一律 `PENDING`**；也不许把"我觉得做完了"写成 `已完成`；
5. 状态变化时**同一次提交**里改这张表，并同步改末尾的汇总计数（守卫会校验两者一致）。

引用规则（这是三张表不互相矛盾的关键）：

- 某个 `ROAD-*` 项**等价于**某条门禁时，本表**只写门禁 ID**、**不复制**它的状态与证据。
  例：`ROAD-M1-006` ↔ `MUST-GATE-010`、`ROAD-M1-004` ↔ `MUST-GATE-006/007`、
  `ROAD-M2-002` ↔ `MUST-GATE-012`、`ROAD-M3-007` ↔ `MUST-GATE-015`、`ROAD-M4-009` ↔ `MUST-GATE-005`。
  **门禁的状态请去 `gate-status.md` 读**，本表只记"这一项是否等价于它"。
- 某项卡在人类裁决上时，本表**只写 `HD-*` 编号**，理由与选项在 `human-decisions.md`。
- 本表的**独有内容**只有三样：路线图原文的要求要点、阶段项粒度上的"还缺哪一部分"、
  以及**不与任何门禁等价**的那些进度（例如"某个模块存在但没接线"）。

**怎么读这张表**（避免三种常见误读）：

1. `PENDING` **不等于"没做"**：`ROAD-M-1-003` 是**未到期**（VST3 属 v2.0.0）、
   `ROAD-M-1-006` 是**只能人做**、`ROAD-M0-003`/`ROAD-M0-006` 是**当前硬件条件下做不出有意义结论**、
   其余是**未实现**。四种性质在各自证据列里分开写了。
2. `部分` **不等于"随便做了点"**：绝大多数 `部分` 是"能力已实现但**没接线**"
   （M2-004 的 `CompensationBank`、M2-005 的 SFZ、M2-008 的 60Hz 心跳、M4-001 的进程内挂载）——
   这与"没做"是两种不同的欠债。
3. **"本地绿"不算绿**：只有 CI 判决算数（`docs/CI_CD.md` §3）。本表的 run id 全部经
   `gh run view <id>` 核实过 `conclusion`；其中 `run 37233109787` **是 failure**，
   已按同代码的净绿 run `37233532606` 引用（见 `ROAD-M0-007` 的备注）。
